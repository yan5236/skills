# 项目记忆使用指南

## 快速开始

### 1. 初始化项目记忆
```bash
node scripts/init-memory.js /path/to/project
```

### 2. 添加新记忆
```bash
node scripts/add-memory.js /path/to/project "架构设计" "采用模块化架构" "架构,模块"
```

### 3. 查询记忆
```bash
# 列出所有记忆
node scripts/query-memory.js /path/to/project --list

# 搜索关键词
node scripts/query-memory.js /path/to/project 架构
```

### 4. 更新记忆
```bash
# 命令行追加内容
node scripts/update-memory.js /path/to/project 001 "新增了用户认证模块"

# 交互式编辑
node scripts/query-memory.js /path/to/project --interactive
```

## 目录结构说明

```
.project-memory/           # 记忆根目录（隐藏目录）
├── INDEX.md              # 索引文件，所有记忆的入口
├── memories/             # 记忆文件目录
│   ├── 001-项目初始化.md
│   ├── 002-架构概览.md
│   └── ...
└── assets/
    └── memory-template.md  # 记忆文件模板
```

## 记忆文件命名规范

- 格式：`{ID}-{简短标题}.md`
- ID格式：3位数字，从001开始
- 示例：`001-项目初始化.md`、`002-技术栈.md`

## 最佳实践

### 何时更新记忆？
1. 完成一个功能模块后
2. 做出重要的架构决策后
3. 项目技术栈发生变化后
4. 代码规范有更新后
5. 对话中提供了重要的项目信息后

### 记忆提炼技巧
- **提取关键信息**：不要记录"我们讨论了什么"，要记录"结论是什么"
- **使用结构化格式**：便于后续检索和更新
- **保持关键词准确**：便于精准检索
- **定期整理**：合并相似内容，删除过时信息

### 记忆内容示例

**好的记忆**：
```markdown
## 架构决策

### 模块划分
- `src/components/` - UI组件
- `src/views/` - 页面组件
- `src/store/` - 状态管理
- `src/api/` - API调用

### 技术选型原因
- 使用 Pinia 而非 Vuex：更轻量，TypeScript支持更好
```

**不好的记忆**：
```markdown
## 对话记录
用户说想要一个后台管理系统，我们讨论了很久，最后决定用Vue...
```
