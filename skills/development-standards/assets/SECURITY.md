## 安全设计原则

- **最小权限**：每个组件、用户、服务只拥有完成其功能所需的最小权限
- **纵深防御**：不在单一层面依赖安全控制，多层防护
- **默认安全**：默认配置应是最安全的选项
- **安全透明**：安全机制应对开发者透明，不易被绕过

## 输入校验

### 通用规则

- 所有用户输入必须校验，不信任客户端校验
- 使用白名单验证而非黑名单

### 防注入

| 攻击类型 | 防护措施 |
|----------|----------|
| SQL 注入 | 参数化查询 / ORM |
| XSS | 输出编码 / CSP 头 |
| 命令注入 | 避免调用系统命令 / 参数白名单 |
| 路径遍历 | 路径规范化 / 限制访问范围 |

## 依赖安全

- 定期运行依赖安全扫描
- 及时更新有已知漏洞的依赖
- 审核第三方依赖的许可证

## 敏感信息管理

- 禁止在代码中硬编码密钥、密码、令牌
- 使用环境变量或密钥管理服务
- 敏感配置文件加入 `.gitignore`

## 安全漏洞检查清单

在每次代码审查和发布前，逐项确认：

- [ ] 输入校验：所有外部输入都经过校验和净化
- [ ] 认证检查：需要认证的接口有有效的认证检查
- [ ] 授权检查：用户只能访问其权限范围内的资源
- [ ] 数据保护：敏感数据在传输和存储中得到保护
- [ ] 错误处理：错误信息不泄露系统内部信息
- [ ] 日志安全：日志中不包含敏感数据
- [ ] 依赖安全：无已知高危漏洞的依赖
- [ ] 配置安全：生产配置已审查，默认密码已修改
- [ ] CSRF 防护：状态变更操作有 CSRF 防护
- [ ] 速率限制：关键接口有速率限制
